# أكاديمية المتداولين العربية | Arabic Traders Academy

منصة مالية عربية (RTL) تضم: لوحة أسواق، أخبار اقتصادية، مفكرة اقتصادية، منصة تحليلات مجانية بتقييم شفاف، شارتات تفاعلية، محلل ذكي، تعليم بشهادات، إدارة وصلاحيات.

**لا توجد بيانات تجريبية في المنتج.** إن لم يتوفر مصدر بيانات يعرض الموقع «غير متاح» مع السبب، ولا يعرض أي سعر أو رقم بديل.

## المتطلبات والتشغيل
- Node.js 22.13 أو أحدث. **بلا أي اعتماديات npm** (يستخدم `node:sqlite` و`fetch` المدمجين).
- `cp .env.example .env` ثم عدّله (على الأقل `PUBLIC_URL` و`ADMIN_EMAIL` و`ADMIN_PASSWORD`). لا حاجة لسر جلسات: الرموز عشوائية وتُخزَّن مجزأة (SHA-256) في القاعدة.
- `npm start` ثم افتح `http://localhost:3000`. أول تشغيل ينشئ حساب المدير من المتغيرين أعلاه، أو شغّل `npm run create-admin`.
- قاعدة البيانات ملف SQLite داخل `DATA_DIR` والصور في `UPLOAD_DIR`. **يجب أن يكونا على قرص دائم** وخذ نسخة احتياطية دورية من مجلد `DATA_DIR` (يكفي نسخ `academy.db` مع ملفي `-wal` و`-shm` أو استخدام `sqlite3 academy.db ".backup"`).
- الاختبارات: `npm test` (تشغّل الخادم الحقيقي مع خادم محاكاة للمزودين يُستخدم **للاختبار فقط**).

|---|---|---|

| المحلل الذكي وملخصات الأخبار بالعربية | `ANTHROPIC_API_KEY` (+ `AI_MODEL`) | الخدمة معطلة بإعلان صريح، لا ردود بديلة |
| القراءات الفعلية في المفكرة | `CALENDAR_PROVIDER=fmp` + `FMP_API_KEY` | المزود الافتراضي (faireconomy) يعطي المتوقع والسابق **بدون الفعلي**، ويُعرض «غير متاح» |
| تأكيد البريد واستعادة كلمة المرور | `SMTP_*` | يعمل الموقع؛ المدير يصدر رابط استعادة يدوياً من لوحة الإدارة |

حصص الذكاء الاصطناعي اليومية: `AI_DAILY_LIMIT_USER` و`AI_DAILY_LIMIT_GUEST`. ميزانية Twelve Data اليومية: `TD_DAILY_BUDGET` (افتراضي 700).

## مصادر البيانات
- **الأسعار**: Twelve Data (REST) وBinance العام. تُخزَّن الأسعار والشموع في SQLite مع وقت الجلب والمصدر وتُعرض بهما، وتخدم من الذاكرة المؤقتة عند فشل المزود.
- **الأخبار**: موجزات RSS/Atom عامة (Fed، ECB، BBC، CNBC، MarketWatch، FXStreet، Investing، OilPrice، Cointelegraph، CoinDesk، Al Jazeera…) قابلة للإضافة والتعطيل من الإدارة. نخزّن العنوان والرابط ومقتطفاً قصيراً ونسبة المصدر فقط. راجع شروط كل موقع قبل الاستخدام التجاري.
- **المفكرة**: faireconomy (غير رسمي) أو Financial Modeling Prep.
- **الذكاء الاصطناعي**: Anthropic Messages API، من الخادم فقط، والمفتاح لا يصل المتصفح.
- حالة كل مصدر ظاهرة في صفحة `/status` وفي لوحة الإدارة.

## الأمان
جلسات بكوكي HttpOnly/SameSite=Lax (Secure في الإنتاج) مع تخزين تجزئة الرمز فقط؛ كلمات المرور بـ scrypt؛ حماية CSRF بترويسة إلزامية؛ تحديد معدل على الدخول والتسجيل والنشر والتعليقات والذكاء الاصطناعي؛ قفل مؤقت بعد محاولات فاشلة؛ رفع صور بفحص البايتات (PNG/JPG/WEBP/GIF) وحدود حجم؛ CSP وترويسات أمان؛ استعلامات SQL معاملة بالمعاملات؛ الصلاحيات تُفرض على الخادم (زائر، عضو، محلل، محرر أخبار، مشرف، مدير) وسجل تدقيق للإجراءات الإدارية.

## منهجية تقييم التحليلات (مختصر، الكاملة في `/methodology`)
نجاح = الهدف الأول قبل الإبطال بشموع حقيقية بعد النشر؛ نفس الشمعة = فشل؛ المستويات غير قابلة للتعديل؛ تعديل النص يُسجَّل علناً؛ الترتيب بحد ويلسون الأدنى 95% بحد أدنى 5 تحليلات محسومة؛ الملغى والمخفي يظهران في سجل المحلل؛ لا شارة «موثّق» دون آلية تحقق.

## إنشاء حساب المدير الأول بأمان
1. اضبط `ADMIN_EMAIL` و`ADMIN_PASSWORD` (كلمة مرور طويلة وفريدة) كمتغيرات سرية في لوحة الاستضافة، لا في ملف داخل المستودع.
2. شغّل الخدمة؛ ينشئ الخادم المدير تلقائياً عند أول إقلاع ويسجّل ذلك في سجل التدقيق.
3. سجّل الدخول من `/login` بالبريد وكلمة المرور، ثم **احذف `ADMIN_PASSWORD` من المتغيرات** (لا يُستخدم بعد وجود مدير).
4. لتغيير كلمة المرور لاحقاً استخدم الإعدادات. وللطوارئ: `npm run create-admin` من طرفية الخدمة.

## النسخ الاحتياطي والاستعادة
- نسخة: `node scripts/backup.js /مسار/النسخ` تنتج `academy.db` (لقطة متسقة) و`uploads.tar.gz`. جدولها يومياً (cron أو Render Cron Job) وانسخها خارج الخدمة.
- استعادة: أوقف الخدمة ثم `node scripts/restore.js /مسار/النسخة/ata-backup-…` ثم شغّلها. تُحفظ القاعدة القديمة بجوارها باسم `.before-restore-*`.
- على Render فعّل أيضاً Snapshots للقرص. على Fly: `fly volumes snapshots list`.

## النشر
**الخيار الأول: Render** (يوفر HTTPS تلقائياً؛ حسب صفحة الأسعار: خدمة ويب مدفوعة بـ 7$ شهرياً (أقل من 1 CPU، 512MB) + قرص دائم 0.25$ لكل GB شهرياً + مساحة عمل Hobby مجانية. الخدمات المجانية لا يؤكَّد أنها تدعم الأقراص، لذا اختر مدفوعة).
1. ارفع المجلد إلى مستودع GitHub خاص (الملف `.gitignore` يستثني البيانات والأسرار).
2. Render ← New ← Blueprint ← اختر المستودع (يقرأ `render.yaml` بقرص 5GB على `/var/data` وNode 22).
3. أدخل المتغيرات السرية المطلوبة عند الطلب (`PUBLIC_URL` بعد معرفة العنوان، `ADMIN_EMAIL`, `ADMIN_PASSWORD`، وما تملكه من المفاتيح).
4. بعد النشر افتح `https://<الخدمة>.onrender.com/status` وتحقق من حالة كل خدمة.

**الخيار الثاني: Fly.io** (ينفع نواة صغيرة بتكلفة منخفضة): `fly launch --no-deploy --copy-config` ثم `fly volumes create ata_data --size 3 --region fra` ثم `fly secrets set ADMIN_EMAIL=… ADMIN_PASSWORD=… PUBLIC_URL=https://<app>.fly.dev ANTHROPIC_API_KEY=…` ثم `fly deploy`. يجب بقاء آلة واحدة فقط (SQLite لا تدعم عدة آلات).

**Docker على أي خادم**: `docker build -t ata . && docker run -d -p 3000:3000 -v ata-data:/data --env-file .env ata` ثم ضعه خلف Caddy/Nginx بشهادة HTTPS.

لم يُنشر هذا المشروع على أي خادم من طرفنا بعد.

## حدود معروفة
- SQLite (ملف واحد) تكفي لحركة متوسطة؛ للتوسع الكبير يلزم الانتقال إلى PostgreSQL.
- محرك الشارت مكتوب داخلياً: شموع، حجم، SMA/EMA/بولينجر/RSI/MACD، خط اتجاه ودعم/مقاومة، مقارنة، لقطة. لا يضاهي TradingView في عدد الأدوات؛ والرسومات تُحفظ في المتصفح.
- الصفحات القانونية نص أساسي يحتاج مراجعة قانونية قبل الإطلاق التجاري.
- التنبيهات داخل الموقع فقط (لا بريد/دفع).
